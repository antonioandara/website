# Internationalization (i18n) guide

This document is the map for keeping the site readable in **English** and
**Spanish**. It has two parts:

1. **Architecture** — how language is wired through the app and how to change
   content in both languages.
2. **Text inventory** — every place user-facing text lives, and whether it is
   already localized or still English-only.

The short version: the main reader and drawing library are fully bilingual and
switch at runtime with the language button next to the theme toggle. The
embedded experiment apps, the LMS demo, the 404 page, and a few static HTML
strings are still English-only and are listed below as the remaining work.

---

## 1. Architecture

### 1.1 Language identity

`src/I18n.elm` defines the single source of truth:

```elm
type Language = English | Spanish
```

It also exposes helpers: `code` (`"en"`/`"es"`), `fromCode` (used for the
browser flag, matches `es*`), `label`, `next`, and `pick language en es`.

Add a locale by adding a constructor here first.

### 1.2 Language lives in the model

`src/FieldManual/Reader.elm` carries the language exactly like the theme:

- `Flags` gains `language : String` (sent from JavaScript).
- `Model` gains `language : Language`.
- `Msg` gains `ToggleLanguage`.
- `update` handles `ToggleLanguage` by calling `I18n.next` and persisting it.
- Port `persistLanguage : String -> Cmd msg` writes the choice to
  `localStorage["manual-language"]`.

Because language is part of `Model`, any view can read
`model.language` and there is no global mutable state.

### 1.3 Interface strings live in `src/Copy.elm`

`Copy.forLanguage : Language -> Strings` returns one typed record. The English
and Spanish values are defined side by side as `en : Strings` and
`es : Strings`, so **the Elm compiler refuses to build if a translation is
missing a field**. That is the safety net that keeps both languages complete.

The record is grouped so it stays easy to scan:

```
Strings
├── title, chapters
├── shell      (skip links, sidebar, cover, header, footer, theme/language labels)
├── home
│   ├── engineering   openSource   experiments
│   ├── magic         journal      videos      connect
├── library    (page title, catalogue heading, filters, count label)
└── lms        (chapter heading + the LMS feature copy)
```

The drawing-catalogue entries are kept as parallel rows so a translator sees
both languages next to each other:

```elm
specimenRows :
    List { key, category, example, en : ( title, caption ), es : ( title, caption ) }
```

`Copy.specimens language` turns those rows into the list the library renders.

### 1.4 Personal content in `src/Content.elm`

`Content.profile` and `Content.journal` are **functions of `Language`**:
`profile : Language -> Profile`, `journal : Language -> List JournalEntry`.
Profile URLs and drawing keys never change; only prose changes.

The magic section and journal prose now live in paired Markdown files under
`content/en/` and `content/es/`. `npm run build:content` validates translations
and generates `src/Generated/Content.elm`. The regular build runs this first.
See [content/README.md](content/README.md) for metadata and authoring rules.

### 1.5 Language selector in the header

`src/SiteShell.elm` renders the selector in `.header-actions`, next to the
theme toggle:

```elm
button [ class "language-toggle", onClick ToggleLanguage, ... ]
    [ span [ class "globe" ] [ text "🌐" ]
    , span [ class "lang-code" ] [ text (String.toUpper (I18n.code model.language)) ]
    ]
```

Styles for `.header-actions` and `.language-toggle` live at the bottom of
`assets/styles.css`; at `max-width: 540px` the theme text is hidden so the
header still fits on a 320 px screen.

### 1.6 Browser side

`assets/app.js` and `assets/library-bridge.js` now:

1. read the stored language (`localStorage["manual-language"]`, falling back to
   `document.documentElement.lang` / navigator),
2. set `document.documentElement.lang` before mounting Elm,
3. pass `language` in the Elm `flags`,
4. subscribe to `persistLanguage` and re-set `lang` + localStorage.

The initial `<html lang="en">` in the HTML files is only a fallback; the runtime
corrects it.

### 1.7 Chapter targets, not titles, are shared

Sidebar/scroll tracking uses stable targets (`engineering`, `journal`, …).
`Main.elm` keeps `chapterTargets` (language independent) and merges them with
`Copy.chapters` (localized titles). Never translate a `target`: it is an HTML
`id` and part of the URL (`index.html#magic`).

### 1.8 How to add or edit a string

1. Find the right record in `src/Copy.elm` (or `src/Content.elm` for profile /
   journal).
2. Add the field to the **type alias** (e.g. `Shell`).
3. Add the English value in `en` and the Spanish value in `es`.
4. Read it in the view: `(Copy.forLanguage model.language).shell.myField`.
5. Run `npx elm make src/Main.elm --output=/dev/null` — a missing translation is
   a compile error, not a runtime surprise.

### 1.9 How to add a new language

1. Add the constructor in `src/I18n.elm` (`French`, …) and update `code`,
   `fromCode`, `label`, `next`.
2. Add a matching value in `Copy.elm` and `Content.elm`. The compiler lists
   every missing field.
3. If the selector is a two-state toggle, turn it into a `<select>` or a cycling
   button. `I18n.all` already returns the supported languages.
4. Optionally add the locale to `<html lang>` handling in `app.js`.

### 1.10 Build and verify

```bash
npm ci
npm run build          # compiles assets/elm.js and assets/library.js
npm test               # tests/site.cjs now covers the language toggle
npm run test:all       # full suite, including experiments and LMS
```

`tests/site.cjs` includes a language section: it switches to Spanish, checks the
`lang` attribute, heading, and persisted theme label, reloads, then switches
back to English.

### 2.3 URLs and SEO (recommended next step)

The current design switches language **at runtime on the same URL**. That is the
fastest way to make the site bilingual, but a crawler only ever sees the initial
HTML (English). If you want the Spanish pages to be indexable:

1. Build separate entry points, e.g. `es/index.html`, `es/library.html`, and a
   translated `es/404.html`.
2. Add reciprocal tags in both heads:
   `<link rel="alternate" hreflang="es" href="https://…/es/index.html">`.
3. Keep `localStorage["manual-language"]` for the in-app toggle, but let the
   path win on first load (a small check in `app.js`).
4. Add `es/*` paths to `scripts/public-files.mjs` so packaging copies them.

This is optional and can be layered on top of the existing model without
touching the Elm views.

### 2.4 Where the Spanish text actually is

Everything for the main reader is in two files:

- **`src/Copy.elm`** — UI copy, section headings, captions, filter labels,
  library specimen titles/captions, LMS card.
- **`src/Content.elm`** — name, identity, introduction.
- **`content/es/`** — magic section and journal entries in Markdown.

Edit the `es = { ... }` record / `Spanish ->` branch. Do not edit the views for
copy changes; the views only decide layout.
